# Calibration Lookup Table Utilities

This directory contains the InFlux workflow for selecting one representative camera calibration result at each lens setting, constructing a calibration lookup table (LUT) over lens focal length (LFL) and focus distance (FD), visualizing selected intrinsic values, and applying the LUT to per-frame lens metadata from processed benchmark videos.

Complete the installation and path configuration in the [InFlux Utility Scripts guide](../README.md) before using this workflow.

## Supported Scope

The supported workflow consumes per-setting calibration experiments produced by the real camera calibration, synthetic board, or synthetic drone pipelines. It selects representative real or synthetic calibration results, constructs and queries LUTs for configured lenses, generates interpolation and leave-one-out diagnostic outputs, produces intrinsics heatmaps, and writes per-frame intrinsics for videos processed with the real-world benchmark video utilities.

## Files

| File | Role |
|---|---|
| `select_trials.py` | Select one representative calibration result for each LFL/FD setting from repeated real or synthetic trials |
| `LUT.py` | Construct and query a LUT, visualize interpolation regions, and generate leave-one-out value records and figures |
| `visualize_results.py` | Generate a heatmap of one selected intrinsic parameter over the LFL/FD grid |
| `generate_real_world_gt.py` | Apply configured LUTs to processed benchmark video metadata and write per-frame intrinsics |
| `utils.py` | Define the generated ground truth filename shared by this workflow |

## Prerequisites

Before using these utilities, prepare the following inputs as needed for the step you intend to run:

- Real or synthetic lens setting files generated by `../select_experiments.py`.
- Completed per-setting calibration experiment folders containing result JSON files and Kalibr initialization logs.
- Processed benchmark video folders from [`../real_world/`](../real_world/) when generating per-frame ground truth.

Run the commands in this guide from `influx/lut_creation/`.

## Configure the Workflow

Edit [`../config.yaml`](../config.yaml) before running the workflow. The `lut_creation` section defines the default selected trial and processed video roots:

```yaml
lut_creation:
  SELECTED_TRIALS_DIR: /path/to/selected/trials
  VIDEO_ROOT: /path/to/processed/benchmark/videos
```

The same configuration file defines the real and synthetic setting-file directories used by `select_trials.py`:

```yaml
LENS_SETTINGS_DIR: /path/to/generated/real/lens/settings
LENS_SETTINGS_DIR_SYNTH: /path/to/generated/synthetic/lens/settings
```

The LUT implementation also uses the configured ARRI camera geometry for its existing thin lens extrapolation behavior, while the keys under `lenses` define the accepted `--lens` values:

```yaml
cameras:
  arri:
    sensor_width_mm: 28.25
    sensor_height_mm: 18.17
    sensor_resolution_x: 3424
    sensor_resolution_y: 2202
    resolution_percentage: 100

lenses:
  <lens_identifier>:
    # Existing lens configuration
```

Use `config.yaml` as the primary source of truth for the default workflow paths. The commands below also accept explicit input and output paths for standalone runs.

## Step 1: Select Representative Calibration Results

`select_trials.py` reads the generated setting grid for one configured lens and finds the experiment corresponding to each `zoom_<i>_focus_distance_<j>` key. For every setting with valid results, it removes outlying trials independently for `fx`, `fy`, `cx`, and `cy`, then selects the remaining trial with the smallest total percentage deviation from the four medians. The selected record retains all eight intrinsic parameters and the initialization parsed from the corresponding first Kalibr trial log.

The experiment root must contain one unambiguous experiment folder for each setting. Folder lookup searches for the `zoom_<i>_focus_distance_<j>` substring and uses the first matching folder, so do not place multiple matching folders for one setting in the same selection root.

Create the parent directory for `--output-filepath` before running the selector. The command overwrites an existing file at the same path. The generated selected trial JSON stores LFL and FD in millimeters.

### Real Calibration Results

A real calibration experiment produced by [`../real_calib/`](../real_calib/) is expected to contain:

```text
<experiment-root>/
└── <name-containing-zoom_i_focus_distance_j>/
    ├── run_metadata/
    │   ├── target_parameters.json
    │   └── actual_parameters.json
    ├── results/
    │   └── trial_<n>_calib_result.json
    └── trial_0/
        └── calibration/
            └── kalibr_calib_log.txt
```

Select representative real results for one lens:

```bash
python select_trials.py \
  --lens canon17 \
  --real \
  --exp-folders-root /path/to/real/experiments \
  --output-filepath /path/to/selected/canon17_selected_trials.json
```

For real experiments, the selected record uses the measured FD from `actual_parameters.json`, in millimeters. The optional `--threshold` interface replaces the selected result with the parsed initialization when either selected principal point coordinate differs from its supplied target by more than the threshold percentage. `--threshold-cx-target` and `--threshold-cy-target` set those targets; the default threshold value `-1` disables this replacement.

### Synthetic Calibration Results

A synthetic experiment is expected to contain exact ground truth intrinsics, evaluation-result JSON files, and the with-guess initialization log used by the selector:

```text
<experiment-root>/
└── <name-containing-zoom_i_focus_distance_j>/
    ├── ground_truth/
    │   └── gt_intrinsics.json
    ├── results/
    │   └── trial_<n>_*eval_result.json
    └── trial_0_with_guess/
        └── calibration/
            └── kalibr_calib_log.txt
```

Choose the result family with `--synth_selection`:

| Value | Result family |
|---|---|
| `new_guess` | Current modified Kalibr with an initial guess; this is the recommended current path |
| `new_normal` | Current modified Kalibr without an initial guess |
| `old_guess` | Original Kalibr with an initial guess |
| `old_normal` | Original Kalibr without an initial guess |

For example:

```bash
python select_trials.py \
  --lens canon17 \
  --synth_selection new_guess \
  --exp-folders-root /path/to/synthetic/experiments \
  --output-filepath /path/to/selected/canon17_selected_trials.json
```

The selected synthetic records retain `gt_data` from each experiment. The current synthetic board workflow primarily produces the `new_guess` family, while the synthetic drone workflow retains all four comparison families. Regardless of the selected family, the selector reads initialization values from `trial_0_with_guess/calibration/kalibr_calib_log.txt`. Synthetic LFL and FD values come from the generated setting file and are stored in millimeters.

## Step 2: Construct and Inspect a LUT

`LUT.py` expects a selected trial file named `<lens>_selected_trials.json` in the selected trials directory. Complete grid cells use trapezoidal bilinear interpolation. Irregular boundary regions use Delaunay triangulation and barycentric interpolation over available drone-based calibration points and adjacent valid grid-edge points when at least three non-collinear points are available.

Run the command-line workflow:

```bash
python LUT.py \
  --lens canon17 \
  --selected-trials-dir /path/to/selected \
  --output-path /path/to/lut_outputs \
  --artifact-path /path/to/lut_artifacts
```

The command creates the output directories as needed and writes:

```text
<output-path>/
└── lut/
    └── <lens>/
        ├── LUT_<lens>.pdf
        └── leave_one_out/
            ├── <lens>_trial_types.pdf
            └── intrinsic_errors/
                └── <lens>_leave_one_out_<intrinsic>_errors.pdf

<artifact-path>/
└── lut_leave_one_out_records/
    └── <lens>_leave_one_out_values.json
```

The `LUT` class accepts query points in the form `[LFL_mm, FD_mm]`. Normal interpolation returns `NaN` outside the supported interpolation regions. With extrapolation enabled, `fx` and `fy` use the existing thin lens extrapolation within supported LFL intervals. For the other intrinsic parameters above the largest supported FD, the query FD is snapped to the interpolated upper boundary before the LUT is evaluated again. Queries outside the supported LFL intervals remain `NaN`.

The leave-one-out outputs record value-level interpolation diagnostics for each intrinsic and the interpolation type used at each setting.

## Step 3: Visualize Selected Intrinsic Values

`visualize_results.py` generates an annotated heatmap for one selected intrinsic parameter:

```bash
python visualize_results.py \
  --path /path/to/selected/canon17_selected_trials.json \
  --intrinsic fx \
  --output_path /path/to/heatmaps
```

The output directory is created as needed, and the command writes:

```text
/path/to/heatmaps/values_fx.pdf
```

Valid intrinsic names are `fx`, `fy`, `cx`, `cy`, `k1`, `k2`, `p1`, and `p2`. Heatmap columns correspond to LFL in millimeters, rows correspond to FD in meters, and missing or invalid settings are annotated as `N/A`.

## Step 4: Apply LUTs to Processed Benchmark Videos

`generate_real_world_gt.py` reads the per-frame metadata produced by [`../real_world/`](../real_world/). Each processed video must contain:

```text
<video-root>/
└── <video-name>/
    └── raw_data/
        └── per_frame_metadata.json
```

The metadata must contain a configured `lens` identifier and a `frames` object whose entries provide `focal_length_mm` and `focus_distance_m`. The selected trials directory must contain `<lens>_selected_trials.json` for every lens listed in `config.yaml`, because the script initializes all configured LUTs before scanning the video root.

Run:

```bash
python generate_real_world_gt.py \
  --video-root /path/to/processed/videos \
  --selected-trials-dir /path/to/selected
```

The input metadata supplies LFL in millimeters and FD in meters. The script converts FD to millimeters for LUT lookup and records it in meters in the generated `lens_metadata` object.

For each recognized video, the command writes:

```text
<video-root>/<video-name>/raw_data/gt_params.json
```

Each generated frame record contains:

```text
intrinsics_gt
intrinsics_gt_extrapolated
lens_metadata
lut_provenance
```

`intrinsics_gt` contains normal in-region interpolation only. `intrinsics_gt_extrapolated` additionally applies intrinsics extrapolation behavior for out-of-region queries. `lut_provenance` records whether normal interpolation is available, the interpolation region type, the contributing LUT vertices, and their weights.

Use `--dry-run` to perform interpolation and print coverage statistics without writing `gt_params.json`.
